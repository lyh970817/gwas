Proof that validation.defaultIgnoreParams = ['genomes'] is honoured
under nf-schema 2.8.0 + Nextflow 26.04.6.

METHOD
------
nf-schema reports unknown params in a "The following invalid input values
have been detected" warning. The probe passes TWO unknown params:

  --genomes           (config says to ignore this one)
  --zzz_probe_param   (nothing ignores this one -- the live-probe control)

A control run forces `validation.defaultIgnoreParams = []` via -c, which must
then report BOTH. Without that control the test could pass vacuously, e.g. if
validation never ran at all.

Command (inside nix-shell, Nextflow 26.04.6, nf-schema 2.8.0), with
GWAS_TEST_FIXTURES pointed at a materialized fixture root:

  nextflow run main.nf -profile test,docker -preview \
      --outdir <tmp> --genomes bogus_value --zzz_probe_param bogus_value

RESULT A -- repo config as-is (defaultIgnoreParams = ['genomes'])
-----------------------------------------------------------------
WARN: The following invalid input values have been detected:
  * --route_profile_resolution.analysis_manifest: <path>
  * --route_profile_resolution.cohort_manifest: <path>
  * --zzz_probe_param: bogus_value

  zzz_probe_param REPORTED  -> probe is live
  genomes     NOT reported  -> defaultIgnoreParams APPLIED

RESULT B -- control, defaultIgnoreParams = []
---------------------------------------------
WARN: The following invalid input values have been detected:
  * --route_profile_resolution.analysis_manifest: <path>
  * --route_profile_resolution.cohort_manifest: <path>
  * --genomes: bogus_value
  * --zzz_probe_param: bogus_value

  zzz_probe_param REPORTED -> probe is live
  genomes     REPORTED     -> defaultIgnoreParams NOT applied

CONCLUSION
----------
The option is honoured, and the probe demonstrably can detect the failure
mode it is testing for. `defaultIgnoreParams` needed no rename: nf-schema
declares the same option name in 2.5.1 and 2.8.0. The
"Unrecognized config option 'validation.defaultIgnoreParams'" warning under
Nextflow 26.04.6 came from nf-schema 2.5.1 being built against Nextflow's
older `nextflow.config.schema.*` plugin API, which was renamed to
`nextflow.config.spec.*` in the Nextflow release that nf-schema 2.6.0
targeted. 2.8.0 is built against the package current Nextflow ships, so the
scope registers and the warnings stop.

SIDE OBSERVATION (pre-existing, not caused by this upgrade)
------------------------------------------------------------
Running without GWAS_TEST_FIXTURES makes validation fail outright:

  * --cohort_manifest (https://raw.githubusercontent.com/nf-core/test-datasets/
    gwas/results/fixtures/relational/cohort_manifest.csv): the file or
    directory ... does not exist

Confirmed independently with curl: that URL returns HTTP 404. The relational
fixtures are not published on the public nf-core/test-datasets gwas branch
yet, so the public fallback path in conf/route_profile_resolver.config cannot
currently validate. This is a fixture-publication gap, unrelated to the
Nextflow or nf-schema upgrade.
