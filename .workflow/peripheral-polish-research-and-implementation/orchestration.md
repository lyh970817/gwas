# Orchestration: Peripheral polish research and implementation

## Execution Rules

- Keep the original objective intact.
- Ask for approval before risky, expensive, external, or destructive actions.
- Keep immediate blocking work local.
- Delegate only bounded, disjoint, materially useful packets.
- Integrate packet results before final verification.

## Branching Rules

1. Complete all eight research packets before editing production files.
2. If local references settle a pattern, cite them and do not browse gratuitously.
3. If a version-sensitive contract is unclear, use official nf-core, MultiQC, Nextflow, or Seqera sources only.
4. Integrate accepted results into one implementation design, recording rejected and conflicting advice.
5. Keep deferred capabilities as local issues, not partial placeholder UI.
6. Stop before any commit, push, deletion, or publication.

## Packet Prompts

Each packet is read-only and must return: local reference evidence, current-repo evidence, official-source evidence if used, recommended exact pattern, anti-patterns, proposed verification, and a concise Markdown distillation suitable for `results/<packet>.md`.

## Completion Audit

- Research results exist and precede production edits.
- Every accepted implementation maps to a packet.
- Deferred features have local issues with clear blockers and acceptance criteria.
- Contributor identity is added without inventing affiliation or ORCID.
- Tests substantiate the original success criteria.
